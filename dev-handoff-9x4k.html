TempleVault Marketing Site

You are being given access to the TempleVault marketing site: a static HTML/CSS site hosted on GitHub Pages at https://www.templevault.net. There is no build step and no framework - edit the files, push to main, and it publishes in under a minute.

Getting Access

  1. Send the site owner your GitHub username. They will add you as a collaborator on the repository.
  2. Accept the invite GitHub emails you.
  3. Clone: git clone https://github.com/ydar996/templevault-home.git
Access is owner-controlled. The site owner can add or revoke your collaborator rights at any time from the repository's Settings > Collaborators. Your access is limited to this repository only - it does not include the TempleVault application, its database, or its servers.

Structure

  • index.html - home
  • features.html - feature detail
  • pricing.html - redirects to https://templevault.net/features (country picker + localized pricing in the app)
  • about.html - about
  • styles.css - shared styles
  • sitemap.xml + robots.txt - SEO plumbing
  • CNAME - custom domain mapping (do not delete)

Must Keep Working

  • Sign in links: https://templevault.net/login
  • Get Started links: https://templevault.net/register
  • Keep at least one visible path to each on every page (nav + footer at minimum).

SEO Requirements

  • Every page needs a unique <title>, <meta name="description">, <link rel="canonical">, and Open Graph tags - update them per page, don't copy-paste.
  • One <h1> per page; semantic headings after that; alt text on all images.
  • sitemap.xml and robots.txt stay at the site root. Update the sitemap if you add or rename pages.
  • Keep (or improve) the JSON-LD SoftwareApplication block in index.html.
  • This handoff page carries noindex - keep it that way and do not link to it publicly.

Preview and Deploy

  1. Preview locally: open index.html in a browser, or run python -m http.server in the repo folder.
  2. Commit and push to main - GitHub Pages republishes automatically within about a minute.
  3. Check the live site after each push.

Reference Docs

  • Site Readme (browser version) - structure, SEO rules, deploy steps
  • README.md and OWNER-GUIDE.md - same content inside the repo

Questions

Send content or scope questions back to the site owner. Do not add forms, trackers, or third-party scripts without approval.
